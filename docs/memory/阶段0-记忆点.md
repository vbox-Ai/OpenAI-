# 阶段 0 记忆点：iOS 编译检查

## 做了什么
- 新建 `.github/workflows/ios-check.yml`：`macos-latest` runner + `aarch64-apple-ios` target
- 执行 `cargo check --target aarch64-apple-ios --workspace`

## 结果
- ✅ 通过（run #1，约 83 秒，conclusion: success）
- 三个 crate（provider-protocol / provider-sdk / providers）全部为 iOS arm64 类型检查通过
- 依赖（rusqlite bundled 的 C 交叉编译、image、TLS 栈等）均编译通过

## 关键结论
- Rust 核心对 `aarch64-apple-ios` 无编译障碍，最大技术风险已排除
- 注意：`cargo check` 只做类型检查、不链接；真正的链接（staticlib + 链接进 Flutter）属于后续阶段

## 下一步（阶段 1）
- 单进程化：`providers` crate 从 `bin` 改成 `staticlib` / `cdylib`（iOS 需要静态链接）
- 抽网关 host 层 + 剥 Tauri
- 用 `cargo build`（不是 check）做真实链接验证
